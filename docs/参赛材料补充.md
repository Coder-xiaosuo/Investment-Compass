## 一、相关项目经验：Investment-Compass

### 1.1 命题映射：从三大难点到工程化破局

本次命题的核心难点可归纳为三个"不"：

**信息整合难**：市场资讯、研报观点、产品信息和客户需求高度分散，多头数据源格式不一、更新频率各异，传统人工整理效率极低。
→ 我们的解法：通过 AkShare 多源数据中台（东方财富主源 + 新浪财经互备），结合统一的数据清洗与质量过滤管道，将行情、财务、资讯异构数据归一为结构化 `market_data` 表；上层 AI 推理无需关心原始数据异构性。更进一步，我们将**每次分析的结构化决策结果**沉淀为 `decision_cards` 全量决策事实层，形成"数据中台 + 决策中台"双层归一。

**服务难规模化**：中小机构投顾人力有限，难以同时覆盖大量客户的个性化需求。
→ 我们的解法：基于 LangGraph 的多 Agent 编排架构（deepagents Harness），将投研分析（估值子 Agent + 技术分析子 Agent）、自选股管理、市场解读等能力拆分为独立子 Agent，由主 Agent 通过意图路由自动委派，实现"千人千面"的对话式服务。同时引入**人机协同（Human-in-the-Loop）**：关键决策节点暂停征求用户意见，机器做分析、用户做判断，兼顾规模化与个性化。

**合规门槛高**：面向个人用户时必须严格避免简单荐股和收益承诺，重视风险揭示、适当性管理和合规留痕。
→ 我们的解法：自研 Enrichment 层将所有 Agent 的错误输出和风险提示收归统一模板管理；决策卡片结构化存储，每笔分析带 `trace_id` 全链路可追溯；**复盘引擎在决策 N 个交易日后自动验证判断对错并回填**，实现"决策—结果—对账"的完整合规留痕；Agent prompt 内置 A 股合规约束（不预测收益、不承诺保本、不代客理财）。

**定位**：面向 中小 B（券商营业部、投顾团队）+ 大 C（高净值个人投资者），以金仕达三十年交易与风控系统能力为底座，借助 AI 工具探索一套覆盖资讯解读、研报摘要、市场观点整理、产品理解、客户画像、风险提示和服务话术生成的全链路智能化助手。

### 1.3 项目概况

Investment-Compass 是一款面向 中小 B + 大 C 的桌面端智能投研分析工具，采用 Electron + Vue 3（前端）+ Python FastAPI + Java Spring Boot（后端）技术栈，实现了从自然语言输入到结构化投资决策、再到事后复盘验证的完整闭环。项目遵循 Harness 工程理念——以 Agent 为执行单元、以 LangGraph 为编排框架、以结构化数据为通信协议的分层架构，确保每层职责单一、可独立测试、可复用替换。

| 维度 | 说明 |
|---|---|
| 项目周期 | 2026 年 3 月至今，持续迭代中 |
| 代码规模 | 前端 ~480KB（压缩后），Python 服务 30+ 模块，Java 后端 20+ 实体/服务 |
| 核心功能 | 人机协同投资分析、K 线技术面分析、价值评估、自选股管理、实时行情、决策复盘与经验进化 |
| 数据源 | 东方财富 AkShare、新浪财经（双源互备） |
| 核心存储 | MySQL（market_data / decision_cards / agent_threads / conversation / message）、Chroma（经验向量库） |

### 1.5 核心模块实现细节

#### 模块一：Agent 编排与意图路由（Harness 编排层）

基于 deepagents（LangGraph 上层框架）构建的多 Agent 编排架构：

```
用户输入 → 主 Agent（create_deep_agent，SYSTEM_PROMPT 定义意图分支）
→ 分支 A 投资分析：委派 value_assessment → HITL 确认 → 委派 technical_analysis
→ 分支 B 纯技术分析：直接委派 technical_analysis
→ 分支 C 自选股管理：委派 watchlist_manage
→ 分支 D 闲聊/概念解释：主 Agent 直接回答
```

关键设计：
- **子 Agent 两种形态**：估值子 Agent 用声明式 SubAgent（纯 LLM 定性 + 工具 + 结构化输出）；技术分析子 Agent 用 CompiledSubAgent（预编译 LangGraph：parse → 策略路由 → LLM 分析 → 落库），确定性的算法流程由代码控制
- **结构化通信协议**：子 Agent 通过 `response_format` 输出 Pydantic 结构化结果（ValuationResult / TechnicalResult），经 ToolMessage 回传主 Agent，杜绝自由文本
- **HITL 人工干预**：主 Agent 配置 `interrupt_on` + 持久化 checkpointer（Redis Stack），投资分析在估值完成后中断征求用户，前端通过 SSE interrupt 事件渲染决策 UI，用户选择后以同一线程 ID 恢复执行

#### 模块二：对话与自选股陪伴

- **市场解读**：主 Agent 基于实时行情与用户对话，生成合规的市场解读与概念解释（分支 D）
- **自选股管理**：WatchlistAgent 支持分组、排序、备注，对接 Java 端完整 CRUD，形成用户关注标的池
- **客户画像雏形**：通过自选股分组与操作历史逐步构建用户风格画像（价值型/成长型/交易型），为个性化服务打基础（迭代中）

#### 模块三：人机协同决策引擎（核心创新）

```
用户输入 → 估值子 Agent（价值评估） → HITL 人工确认 → 技术分析子 Agent → 决策落库
              │                            │                      │
        recommend/reason               用户决定是否               action 由技术面决定
        是否值得进入技术面             进入技术面研究
```

**第一阶段 — 价值评估（value_assessment）**：
1. 规则引擎门控：检查是否提及具体股票、是否存在有效数据、拦截 ST/新股/ROE<0 等异常标的
2. 规则评分器：基于 PE/PB/ROE/营收增速等财务指标的行业百分位打分（70% 行业相对排名 + 30% 绝对值检查）
3. LLM 定性分析：结合财务摘要、维度评分、行业上下文做跨维度定性判断，输出 **recommend（是否推荐进入技术面研究）+ reason（推荐理由）**，替代传统的"硬性分数门控"——估值层从"及格线裁判"变为"研究顾问"

**第二阶段 — 人工干预（HITL）**：
- 估值完成后，系统中断征求用户："是否进入技术面分析"，选项：approve（进入）/ reject（跳过）/ respond（直接回复指令）
- 估值结果（评分/推荐/理由）在前端显式展示，用户基于理由做判断——**机器做分析、用户做判断**，兼顾专业性与适当性管理

**第三阶段 — 技术分析（technical_analysis）**：
- DeepSeek 驱动的价格行为分析，覆盖：趋势结构、支撑阻力、K 线形态、成交量验证、均线系统、MACD 背离
- 内置 A 股特有规则：涨停板/跌停板限制、T+1 交易规则、整数价位心理线
- **最终 action（BUY/SELL/HOLD）由技术面 direction 决定**，决策可解释、可追溯

**决策落库**：每笔分析（含估值摘要、技术结论、当前价格、止损/止盈、市场周期、形态、推理链、trace_id）写入 `decision_cards` 全量决策事实层，作为复盘与经验进化的数据底座。

#### 模块四：经验闭环（核心创新）

```
decision_cards（决策事实层）
      │
      ▼
复盘引擎（review_decisions）── 决策 N 个交易日后取后续行情验证
      │   verdict=HIT/MISS，回填 review_outcome
      ▼
经验提升（promote_experiences）── 已复盘决策提升进 Chroma 精选库
      │   HIT/MISS 通过 tags 区分，幂等 upsert
      ▼
读侧注入（读侧检索）── 新分析时检索先例注入 prompt
      正例（HIT）全分保留；反例（MISS）权重 ×0.5 降权
```

- **复盘引擎**：对已落库的 BUY/SELL 决策，取决策日后 10 根收盘日线验证方向是否兑现（BUY 且后续收盘价上涨 → HIT），回填 verdict / 涨跌幅 / 区间高低 / 实际趋势
- **经验提升器**：将已复盘决策组装为结构化经验条目（估值结论 + 技术结论 + 复盘结果 + 市场周期/板块/形态），幂等写入 Chroma 向量库
- **读侧反例降权**：检索打分时，验证为 HIT 的先例保持原分，MISS 反例权重降为 0.5，保证"失败案例不误导新决策"，且同条件检索中 HIT 排序必然高于 MISS
- **效果**：系统"越用越准"——历史判断对错成为新决策的先验知识，是区别于一次性问答产品的核心进化能力

#### 模块五：可解释决策卡片 + 飞书机器人推送

- **决策卡片**：每笔分析输出结构化的 `card_data` JSON（含估值评分/推荐、技术方向、action、推理摘要、复盘状态），前端渲染为可视化卡片，用户可逐层追溯分析链路
- **复盘状态回填**：卡片支持展示该决策的复盘结果（HIT/MISS、实际涨跌），决策质量事后可见
- **飞书机器人推送**（基于早期 PA_Agent 的飞书通知设计，重构至主系统）：决策完成时向飞书群推送交互卡片（方向/置信度/支撑阻力/估值理由/推理链），支持签名校验与 K 线图片上传——让投顾团队在飞书内即可接收并沉淀决策（demo 前完成）

#### 模块六：K 线技术面可视化

基于 TradingView Lightweight Charts v5 实现专业级 K 线图表：
- 蜡烛图 + 成交量图双图表分离架构（75% + 18% 垂直空间，7% 间隔带）
- 支持 MA/EMA/MACD 等 8 种技术指标叠加
- 日线/周线/月线三级周期（周月线由 Java 后端从日线实时聚合）
- Crosshair 十字光标 + OHLC 悬浮 Tooltip + 键盘导航

### 1.6 数据工程

数据链路：

```
AkShare (东方财富) → Python data_source 层 → 质量过滤 → MySQL market_data → 路由 → 前端
```

- 增量同步：sync_symbols() 自动检测最新交易日，仅拉取缺失数据
- 批量回填：带断点续传的 ThreadPoolExecutor 并发拉取（默认 2 并发，上限 5）
- 智能节流：跨线程共享 AkShare 限流锁，API 调用间隔 ≥ 0.9s，失败自动重试（指数退避，最多 4 次）
- 双源互备：东方财富为主源，新浪财经自动降级

### 2.2 关键架构决策记录

| 决策 | 选项 | 选择 | 理由 |
|---|---|---|---|
| Agent 框架 | LangChain / LangGraph / 自研 | deepagents（LangGraph 上层） | 状态图天然适合多步推理，子 Agent 委派 + HITL 原生支持 |
| 意图识别 | 纯规则 / 纯模型 / 融合 | 模型为主 + 规则兜底 | 规则兜底确保 API 不可用时系统不崩溃 |
| 估值层决策 | 硬性分数门控 / 规则矩阵 / 推荐制 | **推荐制（recommend + reason）** | 估值层从"及格线裁判"变"研究顾问"，判断权交给用户 |
| 决策流程 | 单轮一气呵成 / 人机协同 | **人机协同（HITL 中断）** | 专业判断 + 适当性管理，符合合规要求 |
| 最终动作 | 估值×技术矩阵 / 技术面决定 | **技术面 direction 决定 action** | 买卖信号由市场行为给出，估值负责研究投入判断 |
| 人工干预 | 无 / 前端编排两次调用 / 框架 HITL | **框架 HITL（interrupt/resume）** | 线程级恢复，checkpointer 持久化，天然支持审批语义 |
| 线程状态存储 | Redis / SQLite / MySQL | Redis Stack（AsyncRedisSaver） | 原生支持多 worker/多实例共享与 TTL；MySQL 路线被 langgraph 迁移缺陷阻断（生成列 MD5，错误 3763） |
| 决策数据 | 仅对话展示 / 全量落库 | **decision_cards 全量事实层** | 复盘与经验进化的数据底座 |
| 经验复用 | 无 / 简单 RAG / 复盘驱动 | **复盘驱动 + 反例降权** | 只提升被验证过的决策，MISS 案例降权防误导 |
| 错误处理 | LLM 生成错误解释 / 结构化模板 | 结构化 ErrorContext + 模板层 | 业务代码只产出结构化原因，渲染层统一处理 |

### 2.3 A 股特有规则处理清单

项目在技术分析引擎中内置了以下 A 股特异性规则：
- 涨跌停限制：±10%（主板）、±20%（科创/创业），价格触及限制时暂停买入/卖出建议
- T+1 交易：当日买入不可卖出，避免 Agent 生成同一日买卖的无效建议
- 集合竞价时段：9:15-9:25、14:57-15:00 不生成实盘建议
- 量比验证：量比 >2 确认突破有效，<0.5 缩量警惕
- 整数价位效应：A 股存在明显的整数关口（如 10.00、20.00）心理压力/支撑
- 缺口分析：区分普通缺口、突破缺口、衰竭缺口
