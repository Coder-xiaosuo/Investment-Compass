> 测试日期：2026-07-18  
> 测试版本：v0.1.0  
> 测试范围：价值评估三层流程（闸门→规则评分→LLM重打分）+ PA Agent → 融合决策

---

## 一、测试概述

### 1.1 测试目标

验证价值评估 Agent + 复合分析 Agent 在真实 A 股数据下的全链路正确性，覆盖四种典型场景：

| 场景 | 股票 | 预期 |
|---|---|---|
| 高分白马股 | 贵州茅台 (600519) | 闸门通过 → 规则评分 → LLM重打分 → PA 分析 → 融合决策 |
| ST 拦截 | ST康美 (600518) | 闸门直接拦截（ROE为负） |
| 科技股 | 宁德时代 (300750) | 闸门通过 → 成长性维度高分 → 行业加权生效 |
| 周期股 | 紫金矿业 (601899) | 闸门通过 → 估值维度合理 → 行业加权生效 |

### 1.2 架构

```
用户输入 → evaluate_stock(symbol)
  ├── 数据收集: 财务数据 + 行业分类 + 估值数据 (PE/PB/市值)
  ├── 闸门检查 (gates.py): 毫秒级硬性过滤
  │    └── ST/ROE<0/负债率>90% → 拦截，提前返回
  ├── 规则评分 (scorer.py): 5维度加权，行业调整
  │    └── score<40 → 提前返回（不触发LLM）
  └── LLM重打分 (llm_scorer.py): DeepSeek 深度评判
       └── 输出: final_score + strengths + risks + fair_price_range
            ↓
final_score ≥ 40 → PA Agent 技术分析 → 融合决策矩阵
```

## 三、测试结果

### 3.1 贵州茅台 (600519) — 高分白马 ✅ 全链路

#### 价值评估

| 维度 | 评分 | 权重 | 说明 |
|---|---|---|---|
| 盈利能力 | 81 | 30% | ROE 稳定>20%，毛利率>90% |
| 成长性 | 40 | 25% | 成熟期企业，增速放缓（营收+6.34%） |
| 估值 | 30 | 20% | PE≈31.5，处于历史中位偏高 |
| 财务健康 | 90 | 15% | 负债率仅12%，流动比率7.06 |
| 收益质量 | 60 | 10% | 现金流充沛，盈利质量高 |

**规则评分：59.8 → LLM 调整：+5.2 → 最终评分：65.0（良好）**

LLM 分析摘要：
- **优势**：品牌护城河极深，茅台酒稀缺性和定价权不可复制；财务结构极其健康（负债率12.12%）；现金流充沛
- **风险**：成长性放缓（营收增速6.34%），PE 约30倍缺乏安全边际，消费税改革政策风险
- **意见**：A 股最优质公司之一，适合长期底仓，但短期不宜追高，建议等 PE 回调至25倍以下

#### PA 技术分析

- 耗时：50.03s
- KV-cache 命中率：阶段一 100%，阶段二 63.6%
- 决策类型：decision_card

#### 融合决策

**等买点** — 价值面良好（65分），但技术面未发出强烈买入信号，建议等待更优买点。

## 四、发现的问题与修复

### 问题 1：估值数据 PE/PB 全部缺失

**现象**：所有股票的 `scorer.py` 日志都显示"PE 和 PB 数据均缺失，估值权重转移"。

**根因**：`valuation_service.py` 的 `_fetch_live()` 优先调用新浪接口（`_fetch_from_sina`），该接口只返回基础价格（收盘价），不返回 PE/PB/市值等数据。东方财富接口（`_fetch_from_em`）有完整数据但作为降级备选，从未被调用。

**修复**：修改 `_fetch_live()` 逻辑，优先东方财富接口（含 PE/PB），新浪数据作为基础价格补充，合并两源数据返回。同时加全量数据缓存减少 AkShare 限流风险。

**修改文件**：`services/valuation_service.py`

### 问题 2：AkShare 东方财富接口限流

**现象**：多次调用 `ak.stock_zh_a_spot_em()` 时出现 `RemoteDisconnected` 错误。

**根因**：AkShare 对东方财富接口有请求频率限制。

**修复**：
1. `valuation_service.py` 加内存缓存（60s TTL），同批次请求只拉取一次
2. `run_e2e_test.py` 的 `find_st_stock()` 避免额外调用 EM 接口，直接 fallback 到硬编码 ST 股票

### 问题 3：PA Agent 部分股票 K 线数据缺失

**现象**：宁德时代和紫金矿业的 PA Agent 执行仅 0.01-0.02s（无实际分析），而茅台正常执行 50s。

**根因**：`market_data` 表中缺少 300750 和 601899 的 K 线数据。

**当前状态**：不影响价值评估逻辑验证，不影响融合决策（价值评估 ≥ 60 分时默认"等买点"）。

| 融合决策矩阵 | ✅ 逻辑正确 |
| 串行过滤链（节省 Token） | ✅ 差股提前退出 |

### 6.2 值得关注的问题

1. **评分阈值微调**：茅台规则分 59.8，仅差 0.2 分到 60（良好）。可考虑评分公式边缘微调或调低"良好"线至 55。
2. **PA Agent 数据预加载**：需确保 `sync_service` 能定期同步全市场 K 线数据，避免 PA Agent 因数据缺失跳过。
3. **AkShare 限流稳定性**：内存缓存缓解了同批次限流问题，但生产环境建议用 DB 持久化缓存 + 定时任务同步。
4. **LLM 成本**：约 600 tokens/次，KV-cache 命中~40%，单次成本约 ¥0.001。
