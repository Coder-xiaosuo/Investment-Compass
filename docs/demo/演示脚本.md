# Investment Compass 演示脚本

> 本文档用于指导 Investment Compass（投资罗盘）系统的 Demo 演示，覆盖前置准备、分析模式与操盘模式两条完整交互链路，以及演示过程中的注意事项与应急方案。
>
> 所有内容基于代码实际调研，对应组件路径、接口端点均可在仓库中找到对应实现。

---

## 一、文档说明

- 演示时长建议：分析模式约 8–12 分钟，操盘模式约 6–10 分钟，合计约 20 分钟。
- 推荐演示设备：本地开发机（macOS / Windows），屏幕分辨率 ≥ 1440×900，已安装浏览器（Chrome / Edge 最新版）。
- 推荐演示样例标的：贵州茅台（600519.SH），演示数据相对稳定且画像完整。

### 1.1 系统架构总览

| 服务 | 端口 | 启动方式 | 说明 |
| --- | --- | --- | --- |
| Java 后端 | 8879 | `cd java-backend && mvn spring-boot:run` | context-path 为 `/api`，提供 K 线、会话管理、HITL 流程 |
| Python 服务 | 8002 | `cd python-service && source .venv/bin/activate && python main.py` | 提供 AI 对话、风格画像、基本面、市场概览 |
| 前端 | 5173 | `cd frontend && npm run dev` | Vite 默认端口，三种模式统一入口 |
| MySQL | 3306 | 本地服务 | 数据库 `investment_compass` |
| Redis | 6379 | 本地服务 | 缓存与会话状态 |

外部依赖：
- DeepSeek API Key（必须，通过 `DEEPSEEK_API_KEY` 环境变量注入），无此 Key 则 AI 对话、HITL、子 Agent 均无法运行。

### 1.2 前端两种模式概览

| 模式 | 中间区域 | 右栏 | 左栏 | 切换快捷键 |
| --- | --- | --- | --- | --- |
| 分析模式（analysis） | ChatView（AI 对话板） | RightPanel（画像 Tab + 任务摘要 Tab） | 会话列表（kind=analysis） | `Cmd/Ctrl + 1` |
| 操盘模式（trading） | 三 Tab 看板（技术面 / 基本面 / 市场概览） | RightChatPanel（AI 对话栏） | 会话列表（kind=trading） | `Cmd/Ctrl + 2` |

## 二、前置准备检查清单

### 2.1 环境变量配置

- [ ] `DEEPSEEK_API_KEY` 已正确导出（`echo $DEEPSEEK_API_KEY` 非空），并在 Python 服务启动的同一终端会话中可见。
- [ ] Java 后端配置文件中 MySQL 连接串、Redis 连接串正确（`localhost:3306` / `localhost:6379`）。
- [ ] Python 服务配置中数据库、Redis、DeepSeek 配置项均指向本地或预期环境。
- [ ] 前端 `.env` / Vite 代理配置指向 Java 后端（8879）与 Python 服务（8002）。

### 2.2 服务启动顺序（必须按序）

启动顺序的依据：前端依赖后端 API，Python 服务依赖 DeepSeek 与数据库，Redis/MySQL 是所有后端的基础。

1. **基础中间件**
   - 启动 MySQL（确认 `investment_compass` 库存在）。
   - 启动 Redis（`redis-cli ping` 返回 `PONG`）。
2. **Java 后端**
   - 执行 `cd java-backend && mvn spring-boot:run`。
   - 验证：访问 `http://localhost:8879/api/actuator/health` 或任一已知接口返回 200。
3. **Python 服务**
   - 执行 `cd python-service && source .venv/bin/activate && python main.py`。
   - 验证：日志中无 `DEEPSEEK_API_KEY` 缺失报错，端口 8002 监听成功。
4. **前端**
   - 执行 `cd frontend && npm run dev`。
   - 验证：浏览器访问 `http://localhost:5173` 可正常加载，无控制台红色网络错误。

> ⚠️ 若 DeepSeek Key 未配置，Python 服务虽能启动，但所有 AI 对话、HITL、子 Agent 功能都会失败。演示前务必确认。

### 2.3 数据验证步骤

演示前逐项确认数据可用，避免现场出现"卡片为空"的尴尬：

- [ ] **K 线数据**：`GET http://localhost:8879/api/stock/kline?code=600519.SH&period=daily` 返回非空数组，包含 OHLCV。
- [ ] **市场概览**：`GET http://localhost:8002/api/demo/market-overview` 返回大盘指数、涨跌家数等结构（若 404，见应急方案 7.2）。
- [ ] **基本面**：`GET http://localhost:8002/api/financial/abstract?code=600519.SH` 与 `GET http://localhost:8002/api/valuation?code=600519.SH` 均有数据。
- [ ] **风格画像问题**：`GET http://localhost:8002/api/style_profile/questions` 返回 30 题。
- [ ] **已有画像**：`GET http://localhost:8002/api/style_profile` 若返回空，演示时会触发冷启动问卷（演示前可预先完成一次，避免现场答题占用时间）。
- [ ] **数据库 Demo 数据**：操盘模式看板部分数据来自 `/api/demo/*`，确认 `investment_compass` 中对应表（筹码、资金流、散户人数等）有目标股票的记录。

## 三、分析模式演示流程（analysis）

切换方式：进入应用后默认或在左上角点击"分析模式"，或按 `Cmd/Ctrl + 1`。

### 3.1 步骤 1：冷启动问卷（可选，演示前已预填则跳过）

**操作**：
- 首次打开若弹 `StyleQuizModal`，展示分页问卷（共 30 题，每页 5 题，共 6 页）。
- 演示时如需展示，快速作答 1–2 页后说明"实际用户需答完 30 题"。

**预期效果**：
- 完成最后一页提交后，问卷关闭。
- 右栏"画像 Tab"立刻渲染 `InvestmentProfile` + 六维雷达图（`RadarChart`），维度包括风险偏好、持仓周期、风格倾向等。
- 画像同时持久化到后端，后续进入不再弹窗。

> 💡 演示建议：现场尽量不要完整答题，提前用同一账号完成一次，演示时直接展示已生成的画像，节奏更紧凑。

### 3.2 步骤 2：欢迎页

**操作**：
- 进入或新建一个 analysis 会话，初始展示 `WelcomeCard`。

**预期效果**：
- 大标题 **"Trading with TuanTuan"** 以逐字渐入动画出现。
- 下方 `GuideCards` 展示三张引导卡片：
  - 今日资讯
  - 热门策略
  - 市场大盘
- 点击任一卡片等价于在 `InputArea` 注入对应预设问题。

### 3.3 步骤 3：发送消息

**操作**：
- 在 `InputArea` 输入示例问题，例如 **"分析一下贵州茅台"**。
- 按 `Enter` 发送（`Shift+Enter` 换行）。

**预期效果**：
- 用户消息气泡立即出现在对话流顶部。
- `InputArea` 进入"发送中"禁用态。
- 紧接着出现 AI 回复占位（`StreamingBubble`），开始流式接收。

### 3.4 步骤 4：流式对话与子 Agent

**操作**：等待 AI 流式输出，期间无需操作，可口头讲解。

**预期效果**：
- AI 回复以 **SSE 流式逐块**渲染（Markdown 实时解析）。
- 在对话流中插入 `SubagentCard`，依次展示子 Agent 阶段：
  - 估值子 Agent：实时状态（运行中 / 已完成）。
  - 技术分析子 Agent：实时状态。
- 右栏切换到"任务摘要 Tab"，展示 **Agent Todo 列表**，每项随流程推进实时勾选。
- `ContextUsage`（上下文 token 用量）实时刷新，演示上下文消耗。

> 🎯 讲解话术建议：强调"用户能看到 AI 在做什么，而不是黑盒等待"。

### 3.5 步骤 5：HITL 人工干预（核心亮点）

**操作**：
- 估值子 Agent 完成后，流式输出会**主动中断**。
- 对话流出现 `HITLConfirmCard`，展示估值评分与水平。
- 演示三种选择：
  1. **approve（继续）**：点击后调用 `POST /api/chat/{id}/resume`，流恢复，进入技术分析子 Agent。
  2. **reject（终止）**：流终止，可在下一轮重新提问。
  3. **respond（补充说明）**：在卡片内输入补充信息后提交，同样走 resume 续流。

**预期效果**：
- 选择 approve / respond 后，SSE 续流，技术分析子 Agent 启动，`SubagentCard` 状态推进。
- 整个过程右栏 Todo 列表与 token 用量持续更新。

> 💡 演示建议：默认走 approve 路径以完整展示后续决策卡片；若时间充裕，可演示一次 respond。

### 3.6 步骤 6：决策卡片

**操作**：技术分析子 Agent 完成后，切到右栏"任务摘要 Tab"。

**预期效果**：
- 展示 `DecisionCard`，内容包括：
  - 复合决策（综合结论）。
  - 估值评分与水平。
  - PA 方向（Position Action，仓位方向建议）。
  - 复盘回填区（演示可口头说明"会后可回填实盘结果用于复盘学习"）。
- 决策与对话流结论一致，体现"分析 → 决策"闭环。

### 3.7 步骤 7：右栏画像 Tab

**操作**：切到右栏"画像 Tab"。

**预期效果**：
- 展示 `InvestmentProfile`：六维雷达图（`RadarChart`）。
- 下方展示偏好概要（风险、周期、风格等文字摘要）。
- 演示讲解：画像会影响后续 Agent 的语气与建议倾向。

## 四、操盘模式演示流程（trading）

切换方式：按 `Cmd/Ctrl + 2`，或左上角切换到"操盘模式"。

操盘模式中间区域为三 Tab 看板，右栏为 `RightChatPanel`，每张数据卡片均有"AI 分析"按钮，点击后向右栏注入预设提问。

### 4.1 技术面分析 Tab

切到"技术面分析"Tab，依次展示以下卡片：

| 卡片组件 | 展示内容 | 演示要点 |
| --- | --- | --- |
| `KLineCard` | K 线图（MA5 / MA10 / MA20 / MA30），基于 Lightweight Charts v5 | 鼠标拖拽缩放、十字线悬停查看 OHLC；强调多周期均线同屏 |
| `RetailCountCard` | 散户人数 | 说明散户结构变化对情绪的指示 |
| `ChipCostCard` | 双拼筹码分布 | 指出筹码密集区与当前价位关系 |
| `FundFlowCard` | 资金流向 | 主力 / 散户资金净流入流出 |
| `TargetPriceCard` | 目标价 | 一致预期目标价，辅助决策 |

**AI 分析按钮演示**：
- 在 `KLineCard` 上点击"AI 分析"。
- 右栏 `RightChatPanel` 自动打开，注入预设提问（如"基于当前 K 线形态给出技术面判断"）。
- 右栏以独立对话流式输出，不影响左侧看板。

> 💡 建议只挑 1–2 张卡片点 AI 分析，避免每张都演示导致超时。

### 4.2 基本面分析 Tab

切到"基本面分析"Tab，依次展示：

| 卡片组件 | 展示内容 |
| --- | --- |
| `FinancialSummaryCard` | ROE / ROA / 毛利率 / 净利率 |
| `CashFlowCard` | 经营 / 投资 / 筹资现金流 |
| `ValuationCard` | PE / PB / PS |
| `GrowthCard` | 营收增速 / 利润增速 |
| `SolvencyCard` | 资产负债率 / 流动比率 |

演示要点：
- 强调多维度交叉验证（盈利 + 现金流 + 估值 + 成长 + 偿债）。
- 任何一张卡片同样可点"AI 分析"注入右栏对话。

### 4.3 市场概览 Tab

切到"市场概览"Tab，依次展示：

| 卡片组件 | 展示内容 |
| --- | --- |
| `IndexCard` | 上证 / 深证 / 创业板 / 科创50 指数 |
| `BreadthCard` | 涨 / 跌 / 平家数 |
| `SectorHeatCard` | 板块热力图 |
| `NorthFlowCard` | 北向资金净流入 |
| `VolumeCard` | 成交量 |

演示要点：
- 强调"个股分析离不开大盘环境"。
- 该 Tab 数据来自 Python 服务 `/api/demo/market-overview`，演示前务必验证（见 2.3）。

### 4.4 右栏 AI 对话（RightChatPanel）

**操作**：在任一卡片点击"AI 分析"，或直接在右栏输入框提问。

**预期效果**：
- 右栏独立对话流，与左侧看板解耦。
- 流式输出，支持上下文连续追问。
- 切换不同卡片注入时，对话历史保留，可形成"看板 + 对话"协同。

## 七、注意事项与应急方案

### 7.1 DeepSeek API 超时 / 限流

**现象**：流式对话长时间无输出，或返回限流错误。
**处理**：
- 现场口述"遇到限流，稍候重试"，等待 5–10 秒后重新发送。
- 若持续失败，切换为演示"操盘模式看板"（不依赖 AI），保证演示不中断。
- 提前准备一份历史会话截图 / 录屏，作为兜底素材。

### 7.2 市场概览接口 404

**现象**：`GET /api/demo/market-overview` 返回 404。
**原因**：Python 服务路由未注册或服务未完全启动。
**处理**：
- 确认 Python 服务日志中路由已挂载（搜索 `market-overview` 注册日志）。
- 必要时重启 Python 服务。
- 现场跳过"市场概览 Tab"，主推技术面 + 基本面 Tab。

### 7.3 卡片数据为空

**现象**：操盘模式某卡片显示空态或 loading 一直转。
**处理**：
- 口述"该数据源暂未返回"，切换到下一张卡片。
- 演示前用 2.3 的验证步骤预先排查，提前换标的或补数据。

### 7.4 AkShare 限流

**现象**：K 线或资金流接口偶发空数据。
**原因**：东财历史日线接口限流。
**处理**：
- 演示前 10 分钟提前请求一次预热并缓存。
- 现场如遇空，等待 30 秒重试，或切换到缓存命中的标的。

### 7.5 HITL 卡片未出现

**现象**：估值完成后未中断，直接继续。
**处理**：
- 检查后端 HITL 开关配置是否启用。
- 现场改为演示"完整自动流"，跳过 HITL 讲解，不影响整体闭环。

### 7.6 浏览器 / 前端异常

**现象**：白屏、组件渲染错误。
**处理**：
- `Cmd/Ctrl + R` 硬刷新。
- 仍异常则重启前端 `npm run dev`。
- 极端情况使用录屏兜底。

### 7.7 通用兜底

- **录屏备份**：演示前完整录屏一次（含 AI 对话与 HITL），现场任何环节失败可播放对应片段。
- **备用标的**：准备 2–3 个标的（如 600519.SH、000858.SZ、300750.SZ），主标的数据异常时切换。
- **网络兜底**：确保演示机网络稳定，DeepSeek API 可达。

## 八、演示后问答预案

| 可能问题 | 简要回答方向 |
| --- | --- |
| 数据来源？ | AkShare（东财）+ 自建数据库，Java 后端聚合 K 线，Python 服务聚合基本面与市场 |
| AI 是否可替换？ | 当前用 DeepSeek，客户端有抽象，可替换其他模型 |
| HITL 为什么必要？ | 估值结论影响后续技术分析方向，人工确认避免错误传导 |
| 画像如何影响输出？ | 画像维度注入 Agent prompt，调整语气与建议倾向 |
| 操盘模式数据更新频率？ | Demo 接口为准实时，生产可对接实时行情 |
