# 数据写入链路

> 文档系列：数据中台（`docs/data-platform/`）
> 本文档：02-数据写入链路
> 关联文档：[01-总体架构](./01-总体架构.md) / [03-数据读取规范](./03-数据读取规范.md)

## 1. 定位与职责

Python 服务是数据中台**唯一写入方**。写入链路负责把第三方数据源（AkShare）的行情数据清洗后**幂等落库**到 MySQL，并保证：

- 不突破第三方 API 限流（节流 + 重试 + 并发控制）
- 不写入脏数据（入库前过滤）
- 可重复执行（唯一键 upsert）
- 大批量回填可中断续跑（sync_task 断点续传）

## 2. 写入编排层（sync_service）

入口文件：[sync_service.py](../../python-service/services/sync_service.py)，提供两种写入模式。

### 2.1 增量同步 `sync_symbols`

```
输入 symbols（可带后缀，_strip_suffix 归一为 6 位）
  → AkShareSource.subscribe(code, "1d")
  → 查最新日期 get_latest_market_date
  ├─ 无数据：首次拉 60 根
  └─ 有数据：estimate_days_since 估算需补根数，取 min(N+3, 14)
  → latest_snapshot(fetch_n)（_fetch_with_retry 包装）
  → 过滤：仅保留 trade_date > 最新日期 的新 K 线
  → bars_to_rows → upsert_market_data
  → ensure_stock_metadata 元数据兜底
  → 每只股票后 sleep(1.0) 冷却
```

对应 API：`POST/GET /api/fetch/market`、`POST /api/fetch/sync`；`sync_one_symbol` 通过 `run_in_executor` 将同步放进后台线程，不阻塞 FastAPI 事件循环。

### 2.2 批量历史回填 `batch_fetch`

```
输入 symbols + [start_year, end_year] + concurrency(默认2, 上限5)
  → 每只股票 _process_single_symbol（独立任务）
    → sync_task 断点检查（SUCCESS 直接跳过）
    → 按年循环：东财拉取（失败回退新浪）→ upsert → update_progress
    → 单年失败：mark_partial，继续下一年
    → 全部完成：mark_success / mark_failed
```

对应 API：`POST /api/fetch/batch`、`GET /api/fetch/batch/status`。

## 3. 数据源层（AkShareSource）

入口文件：[akshare_source.py](../../python-service/data_source/akshare_source.py)，支持能力：

| 周期 | 接口（东财） | 回退 | 说明 |
|---|---|---|---|
| 1d | `stock_zh_a_hist`（daily, qfq） | `stock_zh_a_daily`（新浪, qfq） | 批量回填场景的回退在 sync_service 层 |
| 1d 指数 | `stock_zh_index_daily_em` | — | 识别 `is_index_symbol` |
| 1h | `stock_zh_a_hist_min_em`（period=60, qfq） | — | — |
| 4h | 1h 数据重采样 `resample_rows_to_4h` | — | 由 1h 聚合 |

**盘中形成 K 线修正**（`_apply_spot_to_forming`）：交易时段内，用 `stock_individual_info_em` 的最新价修正最新一根未收盘 K 线的 close/high/low，并将 `closed` 标记为 0（正在形成）；非交易时段所有 K 线 `closed=1`。

**时间处理约定**：
- `ts_open`：K 线开盘 Unix 毫秒（UTC）时间戳
- `trade_date`：由 `ts_open` 换算得到的 A 股交易日（`datetime.utcfromtimestamp(ts/1000).date()`）
- 源码内部使用 `Asia/Shanghai` 时区判断交易时段

## 4. 防护机制（三层限流）

| 层 | 机制 | 参数 |
|---|---|---|
| 全局节流 | [akshare_throttle.py](../../python-service/shared/akshare_throttle.py) `throttle()`，跨线程 Lock | 最小间隔 1.2s |
| 同步内节流 | sync_service `_throttle_akshare()`（跨线程全局） | 最小间隔 0.9s |
| 数据源内节流 | AkShareSource `_throttle_akshare()`（模块级） | 最小间隔 0.9s |

**重试策略**（两套并存）：

| 位置 | 次数 | 退避 |
|---|---|---|
| sync_service `_fetch_with_retry` | 3 次 | 递增 2s / 4s |
| AkShareSource `_call_with_retries` | 4 次 | 递减 1~3s，总等待上限 12s |

**内存缓存**：`akshare_throttle.cached(key, ttl=300)` 对财务类低频调用做 5 分钟缓存；`invalidate_stock_cache(symbol)` 支持按股票失效。

**并发控制**：批量回填线程数默认 2（规避东财限流），上限 5；单年间隔 1.5s，单股完成后冷却 1.0s。

## 5. 数据清洗与质量过滤

### 5.1 清洗（shared/ashare_common）

`normalize_ohlcv_df`（列名/类型/缺失标准化）→ `df_to_bars_asc`（升序行）→ `rows_to_kline_bars`（KlineBar 对象，newest-first）。amount 缺失补 0。

### 5.2 入库前过滤（[data_filter.py](../../python-service/shared/data_filter.py)）

`bars_to_rows` 转换后经 `filter_kline_bars` 批量校验，**不合格 K 线直接丢弃并告警**：

| 规则 | 条件 | 判定 |
|---|---|---|
| R1 | open / high / low / close 均 > 0 | 任一 ≤ 0 拒绝 |
| R2 | low ≤ high | 拒绝 |
| R3 | low ≤ close ≤ high | 拒绝 |
| R4 | volume ≥ 0 | 拒绝 |
| R5 | pct_chg 为空或 abs(pct_chg) < 100 | 拒绝 |

## 6. 幂等写入

`market_data_service.upsert_market_data` 使用 MySQL `ON DUPLICATE KEY UPDATE`：

```sql
INSERT INTO market_data
  (symbol, trade_date, timeframe, ts_open, open, high, low, close,
   volume, amount, pct_chg, closed)
VALUES (:symbol, :trade_date, :timeframe, ...)
ON DUPLICATE KEY UPDATE
  open = VALUES(open), high = VALUES(high), low = VALUES(low),
  close = VALUES(close), volume = VALUES(volume), amount = VALUES(amount),
  pct_chg = VALUES(pct_chg), closed = VALUES(closed),
  fetched_at = NOW()
```

- **唯一键**：`symbol + trade_date + timeframe`
- 重复同步只刷新已存在行的价格字段与 `fetched_at`，不产生重复数据
- 单行失败整体回滚（session.rollback）

## 7. 元数据兜底

| 函数 | 触发点 | 行为 |
|---|---|---|
| `ensure_stock_metadata` | 每次同步成功后 | 不存在则查 `stock_individual_info_em` 补名称并插入 |
| `init_metadata` | `POST /api/stock/init-metadata` | 全量初始化：东财 spot 表（`stock_zh_a_spot_em`），失败回退新浪 `stock_zh_a_spot`；识别 INDEX（000300/000016/000905/399001/399006） |

`stock_metadata` 写入同样幂等（`ON DUPLICATE KEY UPDATE`）。

## 8. 批量回填与断点续传（sync_task）

状态管理：[sync_task_service.py](../../python-service/services/sync_task_service.py)。

### 8.1 状态机

```
PENDING ──mark_running──▶ RUNNING ──全部年份成功──▶ SUCCESS
                          │  ├─ 某年失败(其余年份已写入) ──▶ PARTIAL
                          │  └─ 致命异常 ──▶ FAILED
                          ▼
           （重新触发：从 current_year + 1 续传）
```

### 8.2 续传逻辑

- 任务唯一维度：`symbol + start_year + end_year`
- `upsert_task` 已存在则复用原任务（SUCCESS 直接跳过）
- RUNNING 中 `mark_partial`/`mark_failed` 会记录 `current_year` 与 `records_fetched`
- 重跑时 `resume_year = current_year + 1`，已成功年份不再重复拉取

### 8.3 运维观测

Java `/monitor/backfill-progress` 读取 `sync_task` 展示进度；`retry_count` 累加失败次数，`error_msg` 截断 500 字符记录最近错误。

## 9. 失败处理汇总

| 场景 | 处理 | 是否阻断 |
|---|---|---|
| 单股增量失败 | 记录 errors 列表，继续下一只 | 否 |
| 单年批量失败 | mark_partial，继续下一年 | 否 |
| 数据源超时/限流 | 节流 + 重试（见 §4） | 重试后仍失败则降级 |
| 东财失败 | 回退新浪（`_fetch_yearly_data`） | 否 |
| 数据不合法 | data_filter 丢弃 | 否（告警） |
| 数据库异常 | 回滚 + 抛错 | 是 |

## 10. 实时行情（补充）

实时行情链路与历史写入**分离**，由 [quote_publisher.py](../../python-service/services/quote_publisher.py) 负责：

```
AkShare stock_zh_a_spot()
  → 写 Redis Hash quote:{symbol}（仅 6 位 code）
  → Pub/Sub 频道 "quotes" 整批广播
  → Java QuoteRedisSubscriber → WebSocket → 前端
```

- 交易时段内 3s 轮询，非交易时段 60s（`_is_trading_time` 判断）
- 失败静默降级（log warning 后跳过本轮回调）
- **不落 MySQL**；历史归档仍走增量同步
